# タスク: EC ログ分類

EC サイトのアプリケーション / インフラログ 1 行（または 1 イベント）を、
あらかじめ定義したラベルのいずれか 1 つに分類する。

- タスク定義（評価データ・ラベル）: [`task.toml`](task.toml)
- 共通プロンプト: [`prompt.md`](prompt.md)
- データ形式: JSONL（1 行 1 レコード）

```json
{"id": "s001", "text": "<ログ本文>", "label": "payment"}
```

## データセット

| パス | 内容 | コミット |
| --- | --- | --- |
| `data/samples/ec_logs_sample.jsonl` | 疎通確認用の手書きサンプル（16 件） | する |
| `data/samples/ec_logs_synth.jsonl` | 評価用の合成データ（350 件・各ラベル 50 件）。**現在の既定** | する |
| `data/raw/` | 実ログ・公開データセットの生データ | しない |
| `data/processed/` | 前処理・ラベル付け済みデータ | しない |

### 合成データ（`ec_logs_synth.jsonl`）

`src/hellow_jev/synth.py` がラベルごとのテンプレート（各 10 種）にランダムな値（注文番号・SKU・IP・ms など）を
埋めて生成する。seed 固定なので再生成しても同じ内容になる（テストで生成結果とコミット済みファイルの一致を確認）。

```bash
uv run hellow-jev-synth                                              # 既定の 350 件を再生成
uv run hellow-jev-synth --per-label 100 --out data/processed/synth_700.jsonl
```

- サービス名だけで当たらないよう、`payment-svc` の正常ログ・性能ログや `api-gw` の決済エラーなども混ぜている
- 約 2 割は構造化ログ（JSON 1 行）形式
- 限界: テンプレート由来なので実ログより表現の幅が狭く、精度は高めに出やすい。モデル間の相対比較・レイテンシ・コスト計測用と割り切り、実ログが入手できたら差し替える
- テンプレートを変えたら再生成してコミットする（`meta.json` の入力ハッシュで run 間の差分が分かる）

## 評価指標

- Accuracy / Macro-F1 / クラス別 Precision・Recall
- ラベル外出力の率（`invalid_rate`）
- レイテンシ（1 件あたり）
- コスト（API 利用時のトークン数・料金。ローカルの場合は必要リソース）
